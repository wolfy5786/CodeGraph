# Node Labels — desktop / Falkor model

Constraints remain **application-level**. Graph isolation = Falkor **named graph per repository** (`Graph.name`, 1:1 with the repo). Each named graph holds exactly one `:CodeRepository`; the `repo_name` property is retained on nodes for provenance but no cross-repo filtering is required.

---

## Structural labels (always created Phase 1)

| Label | Meaning | Typical properties |
|-------|---------|--------------------|
| `Graph` | Per-repository graph synced with Falkor graph key (1:1 with the repo) | `name` |
| `CodeRepository` | Registered absolute repo root wrapper (exactly one per graph) | `name`, `graph_name`, `local_path`, `last_ingested_at` |
| `Root` | Canonical folder node for repo filesystem root | `path`, `repo_name`, `graph_name`, `absolute_path` |
| `Folder` | Directory subtree | same as Root sans `absolute_path` optional |
| `File` | Real file-system file before SCIP attaches symbols | `path`, `extension`, `language_guess`, `repo_name`, `graph_name` |

Structural nodes seldom carry semantic embeddings.

---

## Phase 1 file-type overlays (still Phase 1, extension driven)

Applied to `:File`-backed ingestion units (excluding structural duplicates). Mutually exclusive categories:

| # | Overlay label | File patterns | Embedding default |
|---|---------------|---------------|-------------------|
| 1 | `SourceFile` | `.java`, `.py`, `.kt`, `.go`, `.rs`, `.cpp`, `.js`, `.ts`, … | **Yes once Phase2+embedding TBD completes** |
| 2 | `Dockerfile` | Dockerfile naming patterns | No |
| 3 | `MarkupFile` | `.json`, `.yaml`, `.yml`, `.xml`, … | No |
| 4 | `Documentation` | `.md`, `.txt`, `.rst`, … | No |
| 5 | `SQLNoSQLScript` | `.sql`, `.cql`, … | No |
| 6 | `CICD` | CI YAML / Jenkinsfiles | No |

_Overlays stack with `:File`; `SourceFile` conflicts with overlays 2-6._

Code symbols extracted via SCIP share base label **`CodeVertex`** alongside the primary definition label assigned in Phase 1 (see next section).

---

## Phase 1 — SCIP definition labels (created from the SCIP index)

Phase 1 parses `index.scip` and creates one code-symbol node per defined symbol,
anchored under its `:File` (or enclosing symbol) via `CONTAINS`. Each node gets a
**primary definition label** derived from `scip_kind` (descriptor suffix as fallback)
plus the base label **`CodeVertex`**. See `PHASE1_IMPLEMENTATION.md`.

| SCIP concept (`scip_kind`) | Primary label | Anchored under |
|----------------------------|---------------|----------------|
| Module / Namespace / Package | `Module` | `:File` |
| Class / Struct / Object | `Class` | `:File` or enclosing symbol |
| Interface / Protocol / Trait | `Interface` | `:File` or enclosing symbol |
| Enum | `Enum` | `:File` or enclosing symbol |
| Method (incl. accessor/operator kinds) | `Method` | enclosing Class / Interface |
| Function | `Function` | `:File` or enclosing symbol |
| Constructor | `Constructor` | enclosing Class |
| Field / Property / Attribute / Variable / Constant / EnumMember | `Attribute` | enclosing Class / Enum |
| Event | `Event` | enclosing symbol |

Every such node also carries `scip_kind` and `scip_descriptor`, which Phase 2 reads
to add overlay labels and relationships **without creating new nodes**.

---

## Phase 2 — Semantic labels (SCIP + regex, no tiers, no LSP)

Phase 2 **adds no new code-symbol nodes and no primary definition labels** — those
are created in Phase 1. It only adds overlay labels, scalar properties, and
relationships, produced by exactly one of two mechanisms — there are no tiers and no LSP:

| Mechanism | Inputs | Labels produced |
|-----------|--------|-----------------|
| SCIP | `scip_kind` + SCIP descriptor + SCIP relationship/occurrence stream | `Object`/`Instance`, `InnerClass`, `External`, `Internal` |
| Regex | per-language source patterns | `Abstract`, `Lambda`, `Destructor`, `Testing`, network/DB/IPC/thread intent labels, `JavaClass`/`JavaInterface`/`JavaEnum` |

`INSTANTIATES` is removed from the design. `SPAWNS` is deferred to a later milestone.

---

## Structural + semantic coexistence cheat sheet

| Label | Typical level | Assigned |
|-------|---------------|----------|
| `Graph` | 0 | Phase 1 |
| `CodeRepository` | 0 | Phase 1 |
| `Root` / `Folder` | 1 | Phase 1 |
| `File` | structural | Phase 1 |
| `Module` / `Class` / `Enum` / `Interface` / callables … | varies | Phase 1 (SCIP definition labels) |
| `Object`/`Instance` / `InnerClass` / `External` / `Internal` | overlay | Phase 2 SCIP labels |

Nodes do **not** include remote blob keys or multi-tenant scope columns; scope is the Falkor graph name (one graph per repository).

## Node properties

### Phase 1 structural + SCIP ingestion

| Property | Type | Description |
|----------|------|-------------|
| `id` | string | Stable ID: `{graph_name}:{relative_path}:{start_line}:{name}` |
| `graph_name` | string | Per-repository graph slug |
| `repo_name` | string | Registered CodeRepository nickname (provenance only; not part of the ID) |
| `name` | string | Symbol / filename |
| `path` | string | Repo-relative path |
| `language` | string | Language tag |
| `start_line`,`end_line` | int | 1-based inclusive span |
| `scip_descriptor` | string | SCIP symbol URI |
| `scip_kind` | int | `SymbolKind` ordinal |
| `signature`,`detail` | string | SCIP / heuristic metadata |

### Phase 2 SCIP labels

Includes `level` (from primary label) and `reference_type_detail` (SCIP type relationship, `Object` nodes only).

### Phase 2 regex properties

Includes `return_type`, `parameter_types`, `access_modifier`, `modifiers`, `annotations`, `is_static` (regex derived).

### Deferred (TBD)

- `embedding`
- richer `docstring`

Raw bodies load from **`CodeRepository.local_path`**.
